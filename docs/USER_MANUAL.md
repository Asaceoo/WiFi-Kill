## 1. 这个软件能做什么

一句话：**让同一 WiFi 下的某台设备"看起来连着网，实际上不了网"。**

它不能：破解 WiFi 密码、免密连网、远程控制别人电脑、查看别人聊天记录。

## 2. 运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位） |
| 网络 | 已连上目标 WiFi 或网线，与目标处于同一网段 |
| 驱动 | Npcap（必须，需勾选 WinPcap 兼容模式） |
| 权限 | 普通用户可尝试；若阻断失败再用管理员 |
| 磁盘 | 约 20 MB |

## 3. 安装（三步）

### 第一步：安装 Npcap

打开 <https://npcap.com/#download>，下载安装包。

> **关键**：安装向导里有一页选项，务必勾选 **`Install Npcap in WinPcap API-compatible Mode`**。
> 不勾这一项，程序能扫描但无法阻断。

安装完成后**重启程序**（若是从旧版本升级，建议重启系统）。

### 第二步：取得程序（三种形态任选其一）

到 [Releases](https://github.com/Asaceoo/WiFi-Kill/releases) 下载下表任一文件：

| 文件 | 形态 | 说明 |
|---|---|---|
| `WiFiKill-vX.Y.Z-setup.exe` | 安装版 | 双击安装，自动建开始菜单与桌面快捷方式，装到 `%LocalAppData%\Programs\WiFiKill`（可写，状态文件正常落盘），可从「应用和功能」正常卸载 |
| `WiFiKill-vX.Y.Z.exe` | 单文件版 | 不安装，拷到任意**可写目录**双击即可，例如 `D:\Tools\WiFiKill\` |
| `WiFiKill-vX.Y.Z-portable.zip` | 打包版 | 解压后含 exe + 本手册 + 技术手册 + 许可协议，适合离线归档分发 |

> 三者功能完全一致。若用单文件版或打包版，**不要放在 `C:\Program Files\`** ——
> 那个目录普通用户不可写，白名单和状态文件会存不下来。安装版由安装程序选好了可写目录，无此问题。

### 第三步：双击运行

首次启动可能有 2–8 秒的空白期（单文件程序需要解包），属正常现象。

## 4. 首次启动会看到什么

程序启动后会自动扫描一次，你大概会看到：

```
┌──────────────────────────────────────────────────────┐
│  WiFiKill   局域网设备与阻断控制   [环境自检][设置] ●就绪│
├──────────────────────────────────────────────────────┤
│  网卡  WLAN · Intel(R) Wi-Fi 6E AX211                 │
│  本机  192.168.1.3   网关 192.168.1.1 f8:79:28:...    │
│  网段  192.168.1.0/24                                 │
├──────────────────────────────────────────────────────┤
│  [扫描设备] [阻断选中] [全阻断] [全部放行]    □隐藏白名单│
├──────────────────────────────────────────────────────┤
│  #  IP 地址        MAC 地址       厂商    类型   状态  │
│  1  192.168.1.1    f8:79:...     —       —     网关   │
│  2  192.168.1.2    ee:89:...     随机MAC 移动设备 白名单│
│  3  192.168.1.3    8c:e9:...     —       —     本机   │
└──────────────────────────────────────────────────────┘
```

如果顶部出现**黄色横条**写着"未安装 Npcap"，说明第一步没做或没勾兼容模式。

如果出现**蓝色横条**写着"未以管理员运行"，先无视它——多数网卡不需要管理员也能发帧，
只有阻断失败时才需要提权。

## 5. 界面逐区说明

### 5.1 顶部徽章

| 显示 | 含义 | 该做什么 |
|---|---|---|
| ● 就绪（绿） | 一切正常 | 可以正常使用 |
| ● 就绪（未提权，绿） | 能扫描，发送能力待验证 | 直接试阻断，失败再提权 |
| ● 需要管理员权限（黄） | 当前网卡拒绝普通用户发帧 | 点「以管理员重启」 |
| ● 未安装 Npcap（黄） | 缺驱动 | 点「打开下载页」 |

### 5.2 网络信息条

| 字段 | 说明 |
|---|---|
| 网卡 | 使用的物理网卡型号 |
| 本机 | 你的 IP 与 MAC |
| 网关 | 路由器 IP 与 MAC（后面这串 MAC 可以用来核对路由器是否被冒充） |
| 网段 | 扫描范围，默认 /24 |

### 5.3 按钮

| 按钮 | 何时可用 | 行为 |
|---|---|---|
| 扫描设备 | 空闲时 | 重新扫描；扫描期间按钮禁用 |
| 阻断选中 | 表格里有选中行 | 阻断选中的设备（可多选） |
| 全阻断 | 表格非空 | 阻断除网关、本机、白名单外的全部设备 |
| 全部放行 | 有设备处于阻断中 | 恢复全部，回填真实 MAC |

### 5.4 设备表状态列

| 状态 | 颜色 | 含义 |
|---|---|---|
| 网关 | 灰 | 路由器，永不阻断 |
| 本机 | 蓝 | 你自己，永不阻断 |
| 白名单 | 紫 | 被保护，跳过阻断 |
| 阻断中 | 红 | 当前已被本程序阻断 |
| 未阻断 | 黑 | 正常 |

### 5.5 系统托盘

关闭窗口不会退出，程序会缩到右下角托盘继续运行（保持阻断）。

| 托盘操作 | 效果 |
|---|---|
| 左键双击 | 唤回主界面 |
| 右键 → 显示主界面 | 同上 |
| 右键 → 全部放行 | 不开窗直接恢复全部设备 |
| 右键 → 退出 | 真正退出；有阻断时先问是否恢复 |

> 想彻底关掉程序，请走托盘右键 →「退出」，不要只点窗口的 ×。

### 5.6 运行日志

每行带时间戳。出问题时这里是第一手线索，例如：

```
00:59:48  已就绪，正在扫描局域网…
00:59:53  主动扫描完成，发现 5 台设备
01:20:11  已阻断 1 台
01:20:45  已放行 1 台，网络应已恢复
```

## 5.7 页脚徽章

窗口底部右侧有一排状态徽章，随时告诉你全局状况：

| 徽章 | 颜色 | 含义 |
|---|---|---|
| 在线 N | 灰绿 | 当前扫描到的设备数 |
| 阻断 M | 灰玫瑰 | 正在被阻断的台数 |
| IPv6 未覆盖 | 驼色 | 本网有 IPv6，当前阻断管不到 IPv6 流量 |
| IPv6 已接管 | 灰绿 | 已在设置里开启 IPv6 定向阻断 |

数值变化时徽章会向上弹一下再落回，扫一眼就知道发生了什么。

## 6. 操作教程

### 教程 A：阻断一台设备

1. 等扫描完成，设备表出现数据
2. 单击目标那一行（按住 `Ctrl` 可多选）
3. 点「阻断选中」
4. 状态列变红显示「阻断中」，日志出现「已阻断 N 台」
5. 验证：那台设备仍显示 WiFi 已连接，但打不开网页

> **安全提示（v2.3.0 起强制）**：网关与本机在任何路径下都**不能被阻断**。
> 即使选中了它们再点「阻断选中」，程序也会跳过并提示 —— 阻断网关会切断
> 整个网络，阻断本机会让自己失联。白名单设备在单目标选择时仍可被**显式**阻断
> （你主动选它 = 明确要断它），只有「全阻断」会自动跳过白名单。

### 教程 B：恢复某台设备

- 单台：右键该行 →「放行选中」
- 全部：「全部放行」按钮

### 教程 C：全阻断（一键清场）

1. 点「全阻断」
2. 弹窗显示**过滤后的台数**（已排除网关、本机、白名单）
3. 确认 → 全部进入阻断中

### 教程 D：保护一台设备不被误伤

1. 右键该行 →「加入白名单」
2. 状态列变紫
3. 之后即使点「全阻断」也会跳过它

白名单同时记录 IP 和 MAC，所以设备换 IP 后依然有效。

### 教程 E：验证配置是否正确（演练模式）

1. 右上「设置」→ 勾选「演练模式」→ 保存
2. 执行一次阻断
3. 日志里会出现 `[演练] 告知 192.168.1.5 ← 192.168.1.1 的 MAC 是 ...` 这样的行
4. **此时不会有任何真实流量发出，也不会写状态文件**

演练模式用于在不影响任何人的前提下检查报文构造是否符合预期。

### 教程 F：程序被强杀后恢复网络

1. 重新打开 WiFiKill
2. 启动时弹窗：「发现残留阻断 N 台，现在恢复吗？」
3. 选「是」→ 自动向那些设备发送真实映射，恢复上网

### 教程 G：复制设备信息

右键设备 →「复制 IP」或「复制 MAC」，可直接粘贴到路由器后台做 MAC 绑定/黑名单。

---

### 教程 H：给设备起名（备注）

1. 右键要标注的设备 → 「设置备注…」
2. 输入名字，例如「小明的 iPad」
3. 「标识」列立即显示这个名字，重启后仍然保留（存在 `aliases.json`）

> 备注按 MAC 保存：设备换了 IP，名字仍然跟着它。
> 右键菜单里出现「清除备注」即可撤销。

## 7. 设置项

| 项 | 默认 | 说明 | 建议 |
|---|---|---|---|
| 重发间隔 | 1.5 秒 | 每隔多久重发一次投毒报文 | 一般够用；目标恢复得快就调到 0.5–1 秒 |
| 演练模式 | 关闭 | 只构报文不发送 | 教学演示、验证配置时开启 |
| IPv6 阻断（实验） | 关闭 | 对本网内的单个目标做 NDP 投毒，切断它经网关的出站流量 | 只有在「本网真有 IPv6 且你确实需要断干净」时才开；同时只能断 1 台 |

> IPv6 断开始终默认关闭，并且**不会记住上次的开关**——每次启动都要重新勾。这是故意的。

> 设置窗口里显示的文件名（`whitelist.txt` / `.wifikill-state.json`）都位于 exe 同级目录。

## 8. 故障排查

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 顶部黄条「未安装 Npcap」 | 没装，或安装时没勾兼容模式 | 重装 Npcap，勾选 WinPcap API-compatible Mode |
| 扫描只有网关和自己 | 网络开了客户端隔离（AP Isolation） | 换网络测试；这是网络策略，无法绕过 |
| 阻断后对方几秒就恢复 | 间隔太大 / 对方 ARP 缓存刷新快 | 设置里把间隔改小 |
| 点阻断无反应，日志无记录 | 目标行已被过滤（网关/本机/白名单） | 看状态列颜色确认 |
| 弹「已在运行」 | 已有实例在跑 | 关掉旧实例；或任务管理器结束 WiFiKill.exe |
| 关闭窗口后仍有设备断网 | 程序缩到托盘了，阻断仍在生效 | 托盘右键 →「全部放行」或「退出」 |
| 找不到程序窗口了 | 已缩到托盘 | 双击托盘图标，或托盘右键 →「显示主界面」 |
| 提示无法获取网关 MAC | 没真正连上网 / 网络刚切换 | 确认能上网后再扫描 |
| 杀毒软件报警 | PyInstaller 单文件 + 网络操作的常见误报 | 核对源码后加入信任 |
| 顶部驼色条「本网已启用 IPv6」 | 你的宽带下发了 IPv6，而 ARP 阻断管不到 IPv6 | 见下方 8.2；或到设置里开 IPv6 阻断 |
| 状态列显示「阻断中·仅v4」 | 目标休眠/静默，程序拿不到它的 IPv6 地址 | 让目标亮屏刷一下网页后重新阻断；或接受只有 IPv4 被断 |
| 勾不上「IPv6 阻断」 | 本网没有 IPv6 默认路由 | 正常现象，这项本来就不适用 |

### 8.1 完全恢复网络（应急）

如果程序异常、找不到界面，手工恢复：

1. 重启一次路由器（最彻底）
2. 或让被断的设备断开 WiFi 再重连（它会重新发 ARP 请求）
3. 或重新打开 WiFiKill，走「发现残留阻断 → 恢复」

---

### 8.2 遇到 IPv6 网络时会发生什么

现在国内大部分宽带都默认下发 IPv6。双栈设备访问同样支持 IPv6 的网站时，
会优先走 IPv6，而 ARP 阻断只能管 IPv4 —— **这时候目标其实还能上网**。

程序的处理方式分三层，从轻到重：

| 层级 | 你会看到什么 | 实际效果 |
|---|---|---|
| 只告警（默认） | 顶部驼色条 + 徽章「IPv6 未覆盖」 | 目标 IPv4 断了，IPv6 仍通 |
| 开启 IPv6 阻断 | 状态列「阻断中·双栈」 | 目标经网关的出站全断 |
| 探明失败 | 状态列「阻断中·仅v4」+ 日志说明 | 只有 IPv4 断，程序明确告诉你没断干净 |

**它管不到的三种情况**（不是 bug，是能力边界）：

1. **局域网内直连**：投屏、AirDrop、手机互传走的是同链路 IPv6，不经过网关，断不了
2. **目标休眠**：拿不到它的 IPv6 地址，只能降级为「仅v4」并如实标注
3. **网络开了客户端隔离**：连目标设备都发现不了，更谈不上 IPv6

如果你需要「保证断干净」，最可靠的办法始终是**在路由器里拉黑 MAC**，那不受任何二层限制。

## 9. 卸载与清理

1. 关闭程序（如仍有阻断，选「是」恢复）
2. 删除程序目录（含 `whitelist.txt`、`.wifikill-state.json`）
3. 如果不再需要抓包能力，可在「添加或删除程序」里卸载 Npcap

卸载本程序**不会**影响网络设置，因为它不修改任何系统配置，只在运行时发 ARP 报文。

## 10. 安全与合规建议

- 只在**你付费或你管理**的网络里使用
- 公司/学校网络使用前，必须先取得 IT 部门的书面许可
- 不要在公共场所（咖啡馆、机场）使用——那里的网络不属于你
- 演示前先告知在场人员，避免被误认为网络故障
- 本程序不采集、不上传任何数据；所有状态只保存在本地文件

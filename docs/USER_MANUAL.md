## 1. 这个软件能做什么

| 能做 | 细节 |
|---|---|
| 列出局域网设备 | IP、MAC、厂商、类型、自定义备注，支持多选 |
| 定向阻断 | 对选中设备做 ARP 双向投毒；保持 Wi-Fi「已连接」但出不去 |
| 全阻断 | 一键清场，自动跳过网关/本机/白名单；检测到 IPv6 时会问是否一并切断 |
| 全部放行 | 回填真实映射，秒级恢复（IPv4 与 IPv6 都算） |
| 占空比限速 | 预设 80/50/20%，或自定义 10–100% 任意百分比：间歇卡顿而非全断 |
| 验证断网 | 逐台判断投毒是否真的生效（被动嗅探，不发新包） |
| 设备名识别 | 被动嗅探 mDNS/LLMNR/NBNS/DHCP，把主机名填进「标识」列（不发包） |
| 导出 | 设备清单与事件流导出 CSV/JSON（Excel 可直接打开） |
| 教学演练 | `--dry-run` 启动即教学模式：绝不发真实报文 |
| 本机守护 | 保护自己不被 ARP/NDP 投毒，发现被篡改自动纠正 |
| 全网哨兵 | 设备基线库：新设备上线告警、投毒者指认、事件留痕 |
| 管理员重启 | 设置里一键提权重启，解决「网卡拒绝普通用户发帧」 |
| 崩溃恢复 / 托盘 / 开机自启 | 状态落盘、关闭缩托盘、可选开机即以管理员启动 |

### 做不到（如实说明）

- **不能破解 Wi-Fi 密码**：只在你已连上的网络里工作；
- **不能真限速**：ARP 层做不到按带宽限速，本程序是占空比节流；
- **断不住同链路 IPv6 直连**：投屏、AirDrop、局域网互传不受影响；
- **验证不等于「彻底没网」**：只证明投毒生效；对方有 IPv6 直连或蜂窝网络时仍能上网；
- **绕不过客户端隔离**：路由器开了 AP Isolation 谁都看不到别人；
- **没有手机版**：仅 Windows 10/11。

## 2. 运行环境

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（64 位） |
| 驱动 | **Npcap**（发二层帧必需，安装时勾选 `WinPcap API-compatible Mode`） |
| 权限 | 多数网卡普通用户可发送；被拒绝时用「以管理员身份重启」 |
| 源码运行 | Python 3.10+（自带 tkinter），`pip install scapy` |
| 网络 | 与目标在**同一二层网络**（同一 Wi-Fi / 同一交换机） |

## 3. 安装

### 3.1 先装 Npcap（关键）

1. 打开 [Npcap 下载页](https://npcap.com/#download) 下载安装包；
2. 安装过程中**务必勾选** `WinPcap API-compatible Mode`；
3. 建议重启一次；程序顶部绿点「就绪」即表示可以发包。

### 3.2 选一种形态

| 形态 | 文件 | 说明 |
|---|---|---|
| 安装版 | `WiFiKill-vX.Y.Z-setup.exe` | 中文向导；**首屏免责声明需勾选同意**；装到 `%LOCALAPPDATA%\Programs\WiFiKill` |
| 单文件版 | `WiFiKill-vX.Y.Z.exe` | 绿色单文件，双击即用；放**可写目录** |
| 打包版 | `WiFiKill-vX.Y.Z-portable.zip` | exe + README + 两份手册 + 概念图 + 许可 |

### 3.3 首次启动

1. 双击运行；单文件版首次自解包约 2–3 秒；
2. 自动扫描局域网，几秒后设备表出现数据；
3. 页脚显示「在线 N」即扫描成功。

## 4. 界面逐区说明

### 4.1 顶部徽章

| 显示 | 含义 | 该做什么 |
|---|---|---|
| ● 就绪（绿） | 一切正常 | 直接使用 |
| ● 就绪（未提权，绿） | 能扫描，发送能力待验证 | 直接试阻断，失败再提权 |
| ● 需要管理员权限（黄） | 网卡拒绝普通用户发帧 | 设置 →「以管理员身份重启」 |
| ● 未安装 Npcap（黄） | 缺驱动，只能扫描 | 装 Npcap 并勾选兼容模式 |

### 4.2 网络信息条

网卡（友好名 · 描述）、本机 IP/MAC、网关 IP/MAC（可与路由器标签比对，判断是否被冒充）、网段。

### 4.3 按钮

| 按钮 | 何时可用 | 行为 |
|---|---|---|
| 扫描设备 | 空闲时 | 重扫局域网，扫描期间禁用 |
| 全选 / 反选 | 任何时候 | 选中全部可见行 / 反选 |
| 阻断选中 | 有选中行 | 阻断选中设备（IPv4 / IPv6 均可多选） |
| 全阻断 | 表格非空 | 阻断除网关/本机/白名单外的全部；双栈时问是否连 IPv6 |
| 全部放行 | 存在阻断 | 恢复全部并回填真实 MAC |
| 验证断网 | 存在阻断 | 逐台判断投毒是否真的生效 |
| 守护本机 | 已扫描到网关 | 切换本机主动防御 |
| 设置 | 任何时候 | 打开设置窗口（含导出设备清单/事件流、以管理员身份重启） |

### 4.4 设备表状态列

| 状态 | 含义 |
|---|---|
| 网关 / 本机 | 受保护，永不被阻断 |
| 白名单 | 被保护，阻断时自动跳过 |
| 阻断中 | 正在投毒（只断 IPv4 显示「阻断中·仅v4」，双栈全断显示「阻断中·双栈」） |
| 限速 N% | 已阻断但按占空比节流，N% 的时间可上网 |
| 未阻断 | 正常 |

### 4.5 右键菜单

| 菜单项 | 作用 |
|---|---|
| 阻断选中 / 放行选中 | 对选中行执行阻断或恢复 |
| 限速（自定义 %）… | 滑杆 10–100%，对选中（未选则全部）已阻断设备生效 |
| 限速 80% / 50% / 20% | 预设档位 |
| 取消限速（恢复全断） | 回到持续投毒 |
| 验证是否已断网 | 对该设备做一次被动嗅探判定 |
| 导出设备清单… | 导出为 CSV/JSON（含 IP/MAC/主机名/厂商/类型/标识/状态/备注） |
| 加入白名单 / 移出白名单 | 白名单设备不再被全阻断扫到 |
| 设置备注… / 清除备注 | 给设备起名（按 MAC 保存） |
| 复制 IP / 复制 MAC | 粘到路由器后台做绑定/拉黑 |

### 4.6 日志与页脚

日志每行带时间戳，是排查第一手线索；页脚显示 **在线 N · 阻断 M · IPv6 状态 · 守护中**。

## 5. 操作教程

### 教程 A：阻断一台设备

1. 等扫描完成；2. 单击目标行（`Ctrl` 多选或「全选/反选」）；3. 点「阻断选中」；
4. 状态列变红「阻断中」，日志出现「已阻断 N 台」；5. 验证：目标仍显示 Wi-Fi 已连接但打不开网页。

> 网关与本机在程序内部被硬性拒绝（API 层），任何入口都阻断不了它们。

### 教程 B：恢复某台设备

单台：右键「放行选中」；全部：「全部放行」（IPv4 与 IPv6 一并停止）。

### 教程 C：全阻断（一键清场，含 IPv6）

1. 点「全阻断」→ 弹窗显示**过滤后**台数；
2. 若本网有 IPv6，弹窗会问「是否同时切断 IPv6 出站」：选「是」→ 本次自动启用 NDP 定向阻断；
3. 确认后全部进入「阻断中」（或「阻断中·双栈」）。

### 教程 D：保护设备不被误伤（白名单）

右键「加入白名单」→ 状态列变紫；同时记录 IP 与 MAC（`whitelist.txt`），换 IP 仍有效。

### 教程 E：验证配置（演练模式）

设置勾选「演练模式」→ 执行一次阻断 → 日志出现 `[演练] 告知 …`；**不发真实包、不写状态、不动本机缓存**。

### 教程 F：程序被强杀后恢复

重新打开 → 弹窗「上次还有 N 台处于阻断…现在恢复吗？」→ 选「是」；换过网络会自动忽略并清除。

### 教程 G：复制设备信息

右键「复制 IP」/「复制 MAC」，直接粘到路由器后台。

### 教程 H：给设备起名

右键「设置备注…」→ 输入名字 → 「标识」列立即显示，重启后仍在（`aliases.json`）。备注按 MAC 保存。

### 教程 I：开启本机主动防御

1. 点「守护本机」（或设置里勾选）；2. 按钮变「守护中」、页脚出现徽章；
3. 检测到投毒自动纠正，页脚显示「守护中·纠正 N」；4. 再点一次即关闭。

> 拿不到可靠基准（缓存与实时询问分歧）时守护会**拒绝启动**，而不是钉死可疑映射。

### 教程 J：批量与多目标（IPv6）

`Ctrl`/`Shift` 多选或用全选；IPv6 在设置开启后同样可多选，每台独立护栏。

### 教程 K：开机自动启动

设置勾选「开机自动启动（管理员）」→ 写入 `HKCU\...\Run` → 下次登录以管理员身份启动并最小化到托盘。

### 教程 L：全网哨兵（新设备告警）

1. 首次扫描后现有设备静默入册；2. 新设备接入 → 托盘通知 + 日志；
3. 设置 →「哨兵事件…」→ 待认领列表可多选认领/移出/全部认领；下方是最近 200 条事件；
4. 检测到投毒会尝试指认攻击者 MAC，结论标注「疑似（MAC 可伪造，供参考）」。

### 教程 M：限速而不是全断

1. 先把目标阻断；2. 右键「限速（自定义 %）…」或预设档；3. 状态列显示「限速 50%」；
4. 效果：10 拍一轮交替投毒/恢复，目标间歇能上网；5. 取消：右键「取消限速（恢复全断）」。

> 占空比随阻断状态落盘，崩溃重启后保持；IPv6 侧不受占空比影响。

### 教程 N：换了 Wi-Fi / 路由器之后

换网后点一次「扫描设备」：程序检测到网卡/网关变化会**主动中止旧阻断**并在日志说明；
在新网络里重新选目标阻断即可。

### 教程 O：验证是不是真的断网了

1. 先有设备「阻断中」；2. 点「验证断网」；3. 4 秒后弹窗逐台给出判定：

| 判定 | 含义 | 怎么办 |
|---|---|---|
| 已生效 | 出站帧正被打到本机 | 保持即可 |
| 部分生效 | 仍有帧直连真实网关 | 调小重发间隔后重验 |
| 未生效 | 目标直连真实网关 | 检查客户端隔离、缓存刷新快 |
| 限速中（N%） | 该设备在限速，直连帧属放行拍 | 正常，无需处理 |
| 无法判定 | 窗口内它没发帧 | 让目标产生流量再验 |

> 只证明投毒生效；目标有 IPv6 直连或蜂窝网络时仍可能上网。

### 教程 Q：把设备清单和事件留档

1. 扫描完成后右键任意设备 → 「导出设备清单…」（或设置窗口同名按钮）；
2. 选保存位置，扩展名选 `.csv`（Excel 直接打开）或 `.json`；
3. 想留档告警与投毒记录：设置窗口 → 「导出事件流…」（时间/类型/IP/MAC/说明）。

> 导出只读本机内存数据，不联网、不上传；文件名自动带日期时间。

### 教程 R：教学演示与源码运行

1. **演练模式**：设置里勾选「演练模式」，所有报文只打印不发送（课堂演示推荐）；
2. **教学模式启动**：`WiFiKill.exe --dry-run`（源码 `python gui.py --dry-run`），
   顶部常驻黄色横幅提示，全程不发出任何真实报文；
3. **从源码运行**：双击 `tools\run_from_source.bat`（首次自动建环境并装 scapy），
   也可加 `--dry-run` 进入教学模式。

### 教程 P：以管理员身份重启

1. 设置窗口左下角点「以管理员身份重启」；2. 若有阻断会先恢复再重启；
3. 确认 UAC 后新实例接管、旧实例退出；4. 取消提权则阻断已恢复、可继续用当前实例。

## 6. 设置项

| 项 | 默认 | 说明 | 建议 |
|---|---|---|---|
| 重发间隔 | 1.5 秒 | 0.5–10 秒，投毒帧重发周期 | 目标恢复快就调 0.5–1 秒 |
| 演练模式 | 关 | 只构造报文不发送；不写状态、不动本机缓存 | 教学演示、验证配置 |
| 启用 IPv6 阻断（实验） | 关 | 对多目标并发做 NDP 投毒，只断经网关出站 | 本网真有 IPv6 且需要断干净 |
| 守护本机（主动防御） | 关 | 持久化（`guard.json`），下次启动自动恢复 | 常驻防护建议开启 |
| 开机自动启动（管理员） | 关 | HKCU Run + UAC 清单 | 需要开机即防护 |
| 哨兵事件…（按钮） | — | 打开哨兵面板 | 有新设备告警后来认领 |
| 以管理员身份重启（按钮） | — | 仅非管理员时出现；先恢复阻断再提权重启 | 网卡拒绝普通用户发帧时用 |
| 识别设备名（本地嗅探） | 开启 | 读 mDNS/LLMNR/NBNS/DHCP 广播推断主机名，不发包、不联网 | 关掉则「标识」列只显示厂商 |

> IPv6 断开始终默认关闭、且**不记住上次开关**——每次启动都要重新勾选（或由全阻断临时开启）。

## 7. 故障排查

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 顶部黄条「未安装 Npcap」 | 没装或没勾兼容模式 | 重装 Npcap，勾选 `WinPcap API-compatible Mode` |
| 扫描只有网关和自己 | 客户端隔离（AP Isolation） | 路由器策略，任何工具绕不过；换网络测试 |
| 阻断后对方几秒就恢复 | 间隔太大 / 缓存刷新快 | 设置里把间隔改小 |
| 限速后没感觉变慢 | 缓存回填太快 | 换 20% 再试；无效改用全断 |
| 点阻断无反应，日志无记录 | 目标行被过滤（网关/本机/白名单） | 看状态列颜色 |
| 点阻断报「二层不可用」 | 缺 Npcap 或权限不足 | 装 Npcap；或「以管理员身份重启」 |
| 弹「已在运行」 | 已有实例 | 关掉旧实例；或任务管理器结束 WiFiKill.exe |
| 关闭窗口后仍有设备断网 | 缩到托盘继续生效 | 托盘右键「全部放行」或「退出」 |
| 双栈网络里目标还能上网 | IPv6 未覆盖 | 看页脚「IPv6 未覆盖」；重做全阻断并选 IPv6 |
| IPv6 阻断没生效 | 未能探明目标 LLA | 日志会写「未能探明…」；让目标产生 IPv6 流量再试 |
| 验证显示「未生效」 | 客户端隔离 / 缓存刷新快 | 调小间隔后重验 |
| 验证显示「无法判定」 | 目标 4 秒内没发帧 | 让目标产生流量后再验 |
| 验证显示「限速中（N%）」 | 目标在限速 | 属预期，放行拍的帧会直连网关 |
| 恢复后仍上不了网 | 恢复帧丢包 | 再点一次「全部放行」；或让对方重连 Wi-Fi |
| 重启后弹恢复提示 | 上次强杀/断电 | 按提示选「是」；换网会自动忽略 |
| 哨兵一直弹新设备 | 设备开随机 MAC（私有 Wi-Fi） | 认领后不再提醒；或关闭设备上的私有地址 |
| 状态文件/白名单丢失 | 程序目录不可写 | 移到可写目录（不要放 `C:\Program Files`） |

## 8. 卸载与清理

| 形态 | 卸载方式 |
|---|---|
| 安装版 | 「设置 → 应用」卸载（或开始菜单卸载项），会一并删除运行时状态文件 |
| 单文件版 / 打包版 | 直接删除 exe / 文件夹 |

程序目录（exe 同级）会产生的文件，全部可安全删除：`.wifikill-state.json`（残留状态）、
`whitelist.txt`（白名单）、`aliases.json`（备注）、`guard.json`（守护开关）、`sentinel.json`（哨兵基线）。

> 若设过「开机自动启动」，请先在设置里取消（或删 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `WiFiKill`）。

## 9. 安全与合规建议

1. 只在自己拥有或已获授权的网络上使用；不确定就不做。
2. 阻断前确认目标不是自己的设备、也不是网关（程序已硬性拦截，但仍要有意识）。
3. 教学演示请用「演练模式」并把风险讲清楚。
4. 用完后及时「全部放行」，不要留下长期阻断。

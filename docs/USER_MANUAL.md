## 1. 这个软件能做什么

WiFiKill 让同一局域网里的**一台指定设备**（或多台）上不了网，而你只需要一台 Windows 电脑：

| 能做 | 细节 |
|---|---|
| 列出局域网设备 | IP、MAC、厂商、类型、自定义备注，支持多选 |
| 定向阻断 | 对选中设备做 ARP 双向投毒；保持 Wi-Fi「已连接」但出不去 |
| 全阻断 | 一键清场，自动跳过网关、本机、白名单；检测到 IPv6 时会问是否一并切断 |
| 全部放行 | 回填真实映射，秒级恢复 |
| 占空比限速 | 对已阻断设备设 80% / 50% / 20%，或自定义 10–100% 任意百分比 |
| 验证断网 | 逐个目标检查投毒是否真的生效（被动嗅探，不发新包） |
| 管理员重启 | 设置里一键提权重启，解决「网卡拒绝普通用户发帧」 |
| 本机守护 | 保护自己不被别人 ARP/NDP 投毒，发现被篡改自动纠正 |
| 全网哨兵 | 设备基线库：新设备上线告警、投毒者指认、事件留痕 |
| IPv6 定向阻断（实验） | 对多个目标并发做 NDP 投毒，切断经网关的 IPv6 出站 |
| 演练模式 | 只打印报文不发送，用于教学与验证 |
| 崩溃恢复 | 强杀/断电后重启，主动询问是否恢复上次的阻断 |

### 做不到（如实说明）

- **不能破解 Wi-Fi 密码**：完全不碰握手与密码，只在你已连上的网络里工作；
- **不能真限速**：ARP 层做不到按带宽限速，本程序做的是占空比节流；
- **断不住同链路 IPv6 直连**：投屏、AirDrop、局域网互传这类不经网关的流量不受影响；
- **绕不过客户端隔离**：路由器开了 AP Isolation，谁都看不到别人；
- **没有手机版**：仅 Windows 10/11。

## 2. 运行环境

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（64 位） |
| 驱动 | **Npcap**（发送二层帧必需，安装时勾选 `WinPcap API-compatible Mode`） |
| 权限 | 多数网卡普通用户可发送；被拒绝时用「以管理员重启」 |
| 源码运行 | Python 3.10+，且解释器自带 tkinter，另需 `pip install scapy` |
| 网络 | 需与目标在**同一个二层网络**（同一 Wi-Fi / 同一交换机） |

## 3. 安装

### 3.1 先装 Npcap（关键）

1. 打开 [Npcap 下载页](https://npcap.com/#download)，下载安装包；
2. 安装过程中**务必勾选** `WinPcap API-compatible Mode`；
3. 安装完成后建议重启一次；
4. 程序里看到顶部绿点「就绪」即表示可以发包。

### 3.2 选一种形态

| 形态 | 文件 | 说明 |
|---|---|---|
| 安装版 | `WiFiKill-vX.Y.Z-setup.exe` | 中文向导；先展示免责声明，需勾选同意；装到 `%LOCALAPPDATA%\Programs\WiFiKill` |
| 单文件版 | `WiFiKill-vX.Y.Z.exe` | 绿色单文件，双击即用；请放在**可写目录** |
| 打包版 | `WiFiKill-vX.Y.Z-portable.zip` | exe + README + 用户手册 + 技术手册 + 概念图 + 许可，解压即用 |

安装版向导要点：

1. 第一页是**免责声明**，必须选「我接受」才能继续；
2. 装完最后一页勾选「打开 Npcap 下载页」可直接去装驱动（必需）；
3. 卸载会一并清理程序目录下的运行时状态文件。

### 3.3 首次启动

1. 双击运行；单文件版首次自解包约 2–3 秒（期间窗口未出现属正常）；
2. 程序自动扫描局域网，几秒后设备表出现数据；
3. 页脚显示「在线 N」即为扫描成功。

## 4. 界面逐区说明

### 4.1 顶部徽章

| 显示 | 含义 | 该做什么 |
|---|---|---|
| ● 就绪（绿） | 一切正常 | 直接使用 |
| ● 就绪（未提权，绿） | 能扫描，发送能力待验证 | 直接试阻断，失败再提权 |
| ● 需要管理员权限（黄） | 当前网卡拒绝普通用户发帧 | 点「以管理员重启」 |
| ● 未安装 Npcap（黄） | 缺驱动，只能扫描 | 装 Npcap 并勾选兼容模式 |

### 4.2 网络信息条

| 字段 | 说明 |
|---|---|
| 网卡 | 正在使用的物理网卡（友好名 · 描述） |
| 本机 | 你的 IP 与 MAC |
| 网关 | 路由器 IP 与 MAC（可与路由器标签比对，判断是否被冒充） |
| 网段 | 扫描范围，默认 /24 |

### 4.3 按钮

| 按钮 | 何时可用 | 行为 |
|---|---|---|
| 扫描设备 | 空闲时 | 重新扫描；扫描期间禁用 |
| 全选 / 反选 | 任何时候 | 选中全部可见行 / 反选当前所选 |
| 阻断选中 | 表格里有选中行 | 阻断选中的设备（IPv4 / IPv6 均可多选） |
| 全阻断 | 表格非空 | 阻断除网关、本机、白名单外的全部设备；双栈网络会问是否连 IPv6 一起断 |
| 全部放行 | 存在阻断（IPv4 或 IPv6） | 恢复全部并回填真实 MAC |
| 守护本机 | 已扫描到网关 | 切换本机主动防御；开启后按钮变「守护中」 |
| 设置 | 任何时候 | 打开设置窗口 |

### 4.4 设备表状态列

| 状态 | 含义 |
|---|---|
| 网关 / 本机 | 受保护，永不被阻断 |
| 白名单 | 被保护，阻断时自动跳过 |
| 阻断中 | 正在双向投毒（只断了 IPv4 时显示「阻断中·仅v4」；双栈全断显示「阻断中·双栈」） |
| 限速 N% | 已阻断但按占空比节流，N% 的时间可上网 |
| 未阻断 | 正常状态 |

### 4.5 右键菜单

| 菜单项 | 作用 |
|---|---|
| 阻断选中 / 放行选中 | 对选中行执行阻断或恢复 |
| 限速（自定义 %）… | 滑杆调 10–100%，对选中（未选则全部）已阻断设备生效 |
| 限速 80%（轻度）/ 50% / 20%（重度） | 对**已阻断**设备设置在线占空比 |
| 取消限速（恢复全断） | 回到持续投毒 |
| 验证是否已断网 | 对该设备做一次被动嗅探判定 |
| 加入白名单 / 移出白名单 | 白名单设备不再被全阻断扫到 |
| 设置备注… / 清除备注 | 给设备起名（按 MAC 保存），显示在「标识」列 |
| 复制 IP / 复制 MAC | 粘到路由器后台做 MAC 绑定/黑名单 |

### 4.6 运行日志与页脚徽章

日志每行带时间戳，出问题时这里是第一手线索；页脚徽章显示 **在线 N · 阻断 M · IPv6 状态 · 守护中**，
数值变化时会弹跳提醒。

## 5. 操作教程

### 教程 A：阻断一台设备

1. 等扫描完成，设备表出现数据；
2. 单击目标行（按住 `Ctrl` 可多选，或用「全选 / 反选」）；
3. 点「阻断选中」；
4. 状态列变红显示「阻断中」，日志出现「已阻断 N 台」；
5. 验证：目标仍显示 Wi-Fi 已连接，但打不开网页。

> 安全提示：网关与本机在**程序内部**被硬性拒绝（API 层），无论从哪个入口都无法阻断它们。
> 白名单设备在单目标选择与全阻断两条路径上都会被跳过。

### 教程 B：恢复某台设备

- 单台：右键该行 →「放行选中」；
- 全部：「全部放行」按钮（IPv4 与 IPv6 阻断一并停止）。

### 教程 C：全阻断（一键清场）

1. 点「全阻断」；
2. 弹窗显示**过滤后**的台数（网关、本机、白名单已排除）；
3. 确认 → 全部进入「阻断中」。

### 教程 D：保护一台设备不被误伤（白名单）

1. 右键该行 →「加入白名单」；
2. 状态列变紫；
3. 之后即使点「全阻断」也会跳过它。

白名单同时记录 IP 与 MAC，设备换 IP 后仍有效（`whitelist.txt`）。

### 教程 E：验证配置是否正确（演练模式）

1. 「设置」→ 勾选「演练模式」→ 保存；
2. 执行一次阻断；
3. 日志出现 `[演练] 告知 192.168.1.5 ← 192.168.1.1 的 MAC 是 ...`；
4. **不会有任何真实流量发出，也不会写状态文件、不动本机缓存**。

### 教程 F：程序被强杀后恢复网络

1. 重新打开 WiFiKill；
2. 弹窗：「上次退出时仍有 N 台设备处于阻断状态…现在恢复它们吗？」；
3. 选「是」→ 自动回填真实映射；
4. 若已换网络（网卡或网关不同），残留记录会被自动忽略并清除，并写日志告知。

### 教程 G：复制设备信息

右键设备 →「复制 IP」或「复制 MAC」，可直接粘贴到路由器后台。

### 教程 H：给设备起名（备注）

1. 右键要标注的设备 →「设置备注…」；
2. 输入名字（如「小明的 iPad」）；
3. 「标识」列立即显示，重启后仍在（`aliases.json`）。

> 备注按 MAC 保存：设备换 IP，名字仍跟着它。右键菜单出现「清除备注」即可撤销。

### 教程 I：开启本机主动防御（守护本机）

1. 扫描完成后点「守护本机」（或在「设置」里勾选「守护本机（主动防御）」）；
2. 按钮变「守护中」、页脚出现绿色「守护中」徽章，日志提示「本机守护已启动」；
3. 此后即使有人对你的网关做 ARP/NDP 投毒，程序会检测并自动纠正，页脚显示「守护中·纠正 N」；
4. 临时停用：再点一次按钮，或到「设置」取消勾选。

> 守护只发「网关真实映射」这一条真实信息，绝不冒充网关、也不打扰其他设备。
> 若拿不到可靠基准（缓存与实时询问出现分歧），守护会**拒绝启动**而不是把可疑映射钉死。
> 检测到投毒后双路纠正：向全网重宣告真实映射（护其他设备）+ 删除本机脏缓存由真实网关重建（护自己）。
> 换 Wi-Fi / 换路由器后守护会自动重估基准，无需手动干预。

### 教程 J：批量选择与多目标阻断

- **多选**：`Ctrl` / `Shift` 点选，或用「全选」「反选」；
- **IPv4**：选中多台后点「阻断选中」，对每台做 ARP 双向投毒；
- **IPv6**：在「设置」开启 IPv6 阻断后同样可多选，对每台独立做 NDP 定向投毒
  （每台目标由独立护栏保护，单台异常不会拖垮其他目标）。

### 教程 K：设置开机自动启动（管理员）

1. 「设置」→ 勾选「开机自动启动（管理员）」→ 保存；
2. 程序写入 `HKCU\...\Run`，值为 `"<exe 路径>" --minimized`；
3. 下次登录以**管理员身份**自动启动并最小化到托盘（会弹一次 UAC 确认）；
4. 若已开启「守护本机」，开机后守护自动在后台生效。

### 教程 L：全网 ARP 哨兵（新设备告警）

1. 首次扫描完成后，当前所有设备自动记入「全网名册」（静默，不弹窗）；
2. 之后有**新设备**接入，右下角弹 Windows 通知 + 日志记录；
3. 「设置」→「哨兵事件…」打开面板：待认领列表可**多选认领**（入册，不再提醒）或**移出**
   （下次出现再提醒），也可「全部认领」；下方是最近 200 条事件历史；
4. 开启守护后若检测到 ARP 投毒，哨兵会尝试**定位攻击者的 MAC**，结论标注为
   「疑似投毒者（MAC 可伪造，供参考）」；
5. 同一事件 5 分钟内只弹一次通知，不会被持续攻击轰炸。

> 哨兵独立于守护运行：不开守护也有新设备告警。基线存于程序目录 `sentinel.json`。

### 教程 M：限速而不是全断（占空比）

1. 先把目标**阻断**（限速只作用于已阻断的 IPv4 目标）；
2. 右键该行 →「限速 80%（轻度）」/「限速 50%」/「限速 20%（重度）」，或「限速（自定义 %）…」用滑杆调任意值；
3. 状态列变「限速 50%」，日志出现「已对 N 台设备设置占空比 50%」；
4. 效果：10 拍一轮，按比例交替发投毒帧（断）与恢复帧（通）——目标间歇能上网，
   体感「一直卡」而不是被踢下线；
5. 取消：右键 →「取消限速（恢复全断）」。

> ARP 层做不了真限速（那需要网关配合），占空比是无需网关协作的唯一诚实做法。
> 边界：目标 ARP 缓存刷新很快时效果会打折；IPv6 侧不受限速影响，仍按 IPv6 开关全断/放行。
> 占空比随阻断状态落盘，程序崩溃/重启恢复后保持。

### 教程 O：验证是不是真的断网了

1. 先有设备处于「阻断中」；
2. 点工具栏「验证断网」（或右键「验证是否已断网」）；
3. 程序对每台做 4 秒被动嗅探，弹窗逐台给出判定：

   | 判定 | 含义 | 怎么办 |
   |---|---|---|
   | 已生效 | 它的出站帧正被打到本机 | 保持即可 |
   | 部分生效 | 仍有帧直连真实网关 | 把重发间隔调小后重试 |
   | 未生效 | 目标直连真实网关 | 检查客户端隔离，或目标缓存刷新太快 |
   | 无法判定 | 窗口内它没发帧 | 让目标产生流量（打开网页/播视频）再验 |

> 验证的是「投毒是否生效」；如果目标还有 IPv6 直连或蜂窝网络，它仍可能上网。

### 教程 P：以管理员身份重启

1. 「设置」窗口左下角点「以管理员身份重启」；
2. 若仍有阻断设备，会先恢复它们再重启；
3. 确认 UAC 弹窗后，新实例以管理员身份接管，旧实例退出；
4. 也可以手动：右键 exe →「以管理员身份运行」。

### 教程 N：换了 Wi-Fi / 路由器之后

1. 换网络后点一次「扫描设备」；
2. 若还有设备处于阻断状态，程序会检测到网卡/网关变化并**主动中止旧阻断**，
   日志提示「网络已变更（旧网关 A → 新网关 B），已中止对旧网络的阻断（N 台）」；
3. 原因：旧阻断的报文发向旧网关，继续跑只会「界面显示阻断中、目标照常上网」；
4. 在新网络里重新选择目标、重新阻断即可。

## 6. 设置项

| 项 | 默认 | 说明 | 建议 |
|---|---|---|---|
| 重发间隔 | 1.5 秒 | 投毒报文的重发周期，范围 0.5–10 秒 | 目标恢复快就调到 0.5–1 秒 |
| 演练模式 | 关闭 | 只构造报文不发送；不写状态文件、不动本机缓存 | 教学演示、验证配置时开启 |
| 启用 IPv6 阻断（实验） | 关闭 | 对多个目标并发做 NDP 投毒，切断经网关的出站流量 | 本网真有 IPv6 且需要断干净时才开 |
| 守护本机（主动防御） | 关闭 | 持续守护本机免遭 ARP/NDP 投毒 | 常驻防护建议开启 |
| 开机自动启动（管理员） | 关闭 | 登录时以管理员身份启动并最小化到托盘 | 需要开机即防护时开启 |
| 哨兵事件…（按钮） | — | 打开哨兵面板：待认领设备 + 事件历史 | 有新设备告警后来这里认领 |

> IPv6 断开始终默认关闭，并且**不记住上次开关**——每次启动都要重新勾选。这是刻意的设计。
> 「守护本机」会持久化（`guard.json`），下次启动按设置自动恢复。
> 设置窗口底部会显示状态文件名，它们都在 exe 同级目录。

## 7. 故障排查

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 顶部黄条「未安装 Npcap」 | 没装，或安装时没勾兼容模式 | 重装 Npcap，勾选 `WinPcap API-compatible Mode` |
| 扫描只有网关和自己 | 网络开了客户端隔离（AP Isolation） | 这是路由器策略，任何工具都绕不过；换个网络测试 |
| 阻断后对方几秒就恢复 | 间隔太大 / 对方 ARP 缓存刷新快 | 设置里把间隔改小 |
| 限速后没感觉变慢 | 目标/网关缓存回填太快 | 换 20% 再试；仍无效就改用全断 |
| 点阻断无反应，日志无记录 | 目标行已被过滤（网关/本机/白名单） | 看状态列颜色确认 |
| 点阻断报「二层不可用」 | 缺 Npcap 或网卡权限不足 | 装 Npcap；或点「以管理员重启」 |
| 弹「已在运行」 | 已有实例在跑 | 关掉旧实例；或任务管理器结束 WiFiKill.exe |
| 关闭窗口后仍有设备断网 | 程序缩到托盘，阻断仍在生效 | 托盘右键 →「全部放行」或「退出」 |
| 找不到程序窗口 | 已缩到托盘 | 双击托盘图标，或托盘右键 →「显示主界面」 |
| 双栈网络里目标还能上网 | 本网有 IPv6，当前只断了 IPv4 | 页脚会显示「IPv6 未覆盖」；按教程 J 开启 IPv6 阻断 |
| IPv6 阻断没生效 | 未能探明目标链路本地地址 | 日志会写「未能探明 … 的 IPv6 地址」；让它产生 IPv6 流量后再试 |
| 恢复后设备仍上不了网 | 恢复帧丢包 | 再点一次「全部放行」；或让对方重连 Wi-Fi |
| 验证显示「未生效」 | 目标缓存刷新快 / 路由开了客户端隔离 | 调小重发间隔再验；隔离属于网络策略，绕不过 |
| 验证显示「无法判定」 | 目标在窗口内没发帧 | 让目标产生流量后再验证 |
| 重启后弹出恢复提示 | 上次是强杀/断电退出 | 按提示选「是」即可恢复；换过网络会自动忽略 |
| 哨兵一直弹新设备 | 设备开了随机 MAC（隐私 Wi-Fi） | 认领后不再提醒；或在设备上关闭「私有 Wi-Fi 地址」 |
| 状态文件/白名单丢失 | 程序目录不可写 | 把程序移到可写目录（不要放 `C:\Program Files`） |

## 8. 卸载与清理

| 形态 | 卸载方式 |
|---|---|
| 安装版 | 「设置 → 应用」里卸载 WiFiKill（或开始菜单里的卸载项）；会一并删除状态文件 |
| 单文件版 / 打包版 | 直接删除 exe/文件夹 |

程序目录（exe 同级）会产生的文件，全部可安全删除：

| 文件 | 内容 |
|---|---|
| `.wifikill-state.json` | 残留阻断状态（删除=不再提示恢复） |
| `whitelist.txt` | 白名单 |
| `aliases.json` | 设备备注 |
| `guard.json` | 守护开关 |
| `sentinel.json` | 哨兵基线与事件流 |

> 若曾设置「开机自动启动」，请先在设置里取消勾选（或删除注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `WiFiKill` 值）。

## 9. 安全与合规建议

1. **只在自己拥有或已获授权的网络上使用**；不确定就不做。
2. 阻断前先确认目标不是你自己的设备、也不是网关（程序已硬性拦截，但请自己心里有数）。
3. 教学演示请用「演练模式」，并把风险讲清楚。
4. 用完后及时「全部放行」，不要留下长期阻断。
5. 不要把本程序用于任何形式的骚扰、勒索或竞争打击——那已经超出工具的使用范畴。
